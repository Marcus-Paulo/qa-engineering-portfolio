# 05 — Documentação e análise de bugs

## Objetivo
Demonstrar como registrar defeitos de forma objetiva, reproduzível e útil para desenvolvimento e produto.

## Modelo de relato
1. **Título:** resumo direto do comportamento incorreto;
2. **Ambiente:** aplicação, versão, navegador/dispositivo e ambiente;
3. **Pré-condições:** estado necessário para reproduzir;
4. **Passos:** sequência numerada e objetiva;
5. **Resultado atual:** comportamento observado;
6. **Resultado esperado:** comportamento previsto;
7. **Evidências:** imagens, vídeos, logs ou requisições sem dados sensíveis;
8. **Impacto:** usuários e funcionalidades afetadas;
9. **Severidade/prioridade:** justificativa baseada no impacto e urgência.

## Exemplos planejados
- [ ] Defeito funcional em formulário;
- [ ] Inconsistência entre interface e API;
- [ ] Regressão após alteração;
- [ ] Problema de validação ou permissão.

Os exemplos serão reproduzidos em uma aplicação fictícia ou pública, sem copiar tickets ou informações internas de empresas.
